# Supa Dev

Лёгкое приложение на Rust для готового окружения **Qwen Code + qwen-work** на Windows и Linux x64.
Настраивает облачный Qwen, локальный редактор промптов и гейтвей, создаёт команду `qwen-work` и открывает проект в терминале.

## Запуск

1. Скачайте сборку из [Releases](https://github.com/Supa-Doge/supa-dev/releases): `supa-dev-windows-x86_64.exe` или `supa-dev-linux-x86_64`.
2. На Linux выполните `chmod +x supa-dev-linux-x86_64`, затем запустите файл. Нужны графическая сессия X11/Wayland, OpenGL и glibc 2.35+ (например, Ubuntu 22.04+).
3. В разделе **Настройка** вставьте **QwenCloud → Token Plan API Key**, укажите рабочую папку и сохраните. Можно импортировать уже сохранённый локальный ключ Qwen.
4. Нажмите **Установить / восстановить**. Повторный запуск использует готовые компоненты и продолжает прерванное скачивание модели.
5. Выберите папку проекта и нажмите **Запустить Qwen в терминале**, либо откройте новый терминал и выполните `qwen-work`.

Пример: `qwen-work --project /path/to/project --resume`. Остальные аргументы передаются Qwen без изменений. Внутри Qwen доступны `/model`, инструменты, MCP и обычные команды. По умолчанию применяется `--approval-mode=yolo`, как в командной инструкции; это переключается в настройках, а явный аргумент CLI имеет приоритет.

## Что устанавливается

| Компонент | Источник / поведение |
|---|---|
| Интерфейс | Rust + egui, без браузерного движка |
| Qwen Code + Node.js | Официальный standalone-установщик Qwen; существующая standalone-установка используется повторно |
| LM Studio | Существующая LM Studio Desktop или официальный фоновый runtime **llmster**, без отдельного окна LM Studio |
| Локальная модель | `huihui-ai/Huihui-Qwen3.8-27B-abliterated-GGUF`, `Huihui-Qwen3.8-27B-abliterated-Q4_K.gguf`, 16.8 GB |
| Python | Автоматически скачиваемый собственный runtime с проверкой SHA-256; системный Python и pip не нужны |
| Гейтвей и загрузчик | Встроены в исполняемый файл; исходники находятся в `backend/` |

Версия модели и её SHA-256 закреплены в [local-model.json](backend/config/local-model.json). Python закреплён в [runtime-manifest.json](assets/runtime-manifest.json). Скрипты загрузки Qwen и LM Studio берутся с официальных HTTPS-адресов при установке. Они устанавливают актуальные версии поставщиков; уже установленный Qwen можно обновлять штатным `/update`.

Модель требует до **34 GB свободного места** на время скачивания и сборки частей, после чего остаётся 16.8 GB. Для быстрого редактора желательна NVIDIA с 24 GB VRAM; загрузчик учитывает свободную видеопамять и допускает частичную выгрузку на CPU. Без обнаруженной NVIDIA используется CPU при достаточной RAM; редактирование на CPU существенно медленнее. Полный GPU offload не гарантируется, если память занята другими приложениями. Модель загружается в память только при необходимости исправить отклонённый запрос.

## Маршрут запросов

```text
Qwen Code → localhost:1236 → облачный Qwen
                                  │ HTTP 400
                                  ↓
                        локальный редактор :1234
                                  │ изменённый текст
                                  ↓
                            облачный Qwen
```

Локальная модель **только редактирует текст**. Она не получает исполняемых инструментов, не выполняет задачу, а её ответ не подставляется вместо облачного ответа. Гейтвей сохраняет роли, системные инструкции, вызовы инструментов, параметры, пути и числовые значения. Он может нейтрализовать постороннюю грубую или откровенную прозу в истории, сохраняя техническую задачу. Это не гарантирует принятия любого запроса: после двух неудачных циклов возвращается ошибка облака.

Модель, выбранная через `/model`, сохраняется между запусками. Выбор в приложении применяется вновь, когда вы меняете его в настройках. Пользовательские инструменты и MCP не отключаются. Порт гейтвея по умолчанию 1236, чтобы не конфликтовать с прежним локальным артефактом на 1235.

## Ключи и обновления

Командный ключ **не включён** в код или сборку. Каждый разработчик вводит свой ключ в приложении. На Windows ключи защищены DPAPI текущего пользователя, на Linux хранятся в каталоге с правами 0700 и файле с правами 0600. В обычный журнал ключи и тела запросов не записываются.

Репозиторий приватный. Для скачивания обновлений войдите через `gh auth login` либо укажите в приложении GitHub-токен с доступом к этому репозиторию (**Contents: read**). Также поддерживаются `GH_TOKEN` и `GITHUB_TOKEN`. Для fine-grained токена организация может требовать предварительного одобрения.

Приложение проверяет последний стабильный релиз при запуске и раз в 6 часов, скачивает сборку для своей ОС, проверяет SHA-256 из GitHub asset digest или `SHA256SUMS` и предлагает перезапуск. Старая версия сохраняется рядом с программой как `.previous`. Запущенные терминалы работают независимо от интерфейса. Гейтвей обновляется при следующем запуске, когда у него нет активного запроса. Не закрывайте приложение во время установки; сначала нажмите **Отменить**.

Настройки, собственный Python, скрипты и загрузки находятся в локальном каталоге данных SupaDev (путь виден в настройках), рабочий кэш — в выбранной папке `qwen`. Переменная `SUPA_DEV_HOME` позволяет задать отдельный каталог приложения. Профиль Qwen хранится отдельно в `qwen-profile`; при первом запуске копируются существующие настройки без блока с ключами. Изменяемые shell-профили сохраняются в `.supa-backup-*`; существующая команда `qwen` не заменяется. На Windows алиас добавляется в профили Windows PowerShell и установленного PowerShell 7; на Linux — в `~/.local/bin` и PATH bash/zsh.

## Разработка и релизы

Требования для сборки: Rust 1.93, Node.js 22+, Python 3.10+ для тестов; для Windows — MSVC Build Tools. На Linux нужны заголовки X11/Wayland/OpenGL (список в workflow).

```powershell
# Windows
./scripts/build.ps1
python backend/scripts/test-gateway-repair.py --synthetic-only
python backend/scripts/test-runtime.py
```

```bash
# Linux
bash scripts/build.sh
python3 backend/scripts/test-gateway-repair.py --synthetic-only
python3 backend/scripts/test-runtime.py
```

`cargo fmt --check` и `cargo test --locked` проверяют Rust. `supa-dev --diagnose` скачивает собственный Python при необходимости и выводит состояние компонентов в JSON, не создавая алиас и не выполняя облачные задачи. `--bootstrap` только разворачивает runtime. Для изолированной проверки задайте `SUPA_DEV_HOME`.

GitHub Actions проверяет оба целевых окружения. Тег `vX.Y.Z`, соответствующий версии в `Cargo.toml`, запускает сборку Windows/Linux и публикует обе программы с `SHA256SUMS` в Releases. В репозиторий включены нужные скрипты из исходного рабочего окружения; история чатов, проекты, кэш, диагностические запросы и ключи исключены.

Официальные источники: [Qwen Code](https://github.com/QwenLM/qwen-code), [LM Studio headless](https://lmstudio.ai/docs/developer/core/headless), [Python](https://www.python.org/downloads/), [Python Build Standalone](https://github.com/astral-sh/python-build-standalone), [репозиторий модели](https://huggingface.co/huihui-ai/Huihui-Qwen3.8-27B-abliterated-GGUF).
