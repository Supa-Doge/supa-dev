# Supa Dev

Лёгкое приложение на Rust для готового окружения **Qwen Code + qwen-work** на Windows и Linux x64.
Настраивает облачный Qwen, локальный редактор промптов и гейтвей и открывает проект в терминале кнопкой в приложении.

## Запуск

1. Скачайте сборку из [Releases](https://github.com/Supa-Doge/supa-dev/releases): `supa-dev-windows-x86_64.exe` или `supa-dev-linux-x86_64`.
2. На Linux выполните `chmod +x supa-dev-linux-x86_64`, затем запустите файл. Нужны графическая сессия X11/Wayland, OpenGL и glibc 2.35+ (например, Ubuntu 22.04+).
3. При первом запуске мастер попросит **QwenCloud → Token Plan API Key**. Можно импортировать уже сохранённый локальный ключ Qwen.
4. Укажите рабочую папку, выберите облачную модель из списка и нажмите **Установить окружение**. Повторный запуск использует готовые компоненты и продолжает прерванное скачивание модели. Установку можно отложить и запустить позднее из приложения.
5. Выберите папку проекта и нажмите **Запустить Qwen в терминале**.

Приложение не создаёт алиасы и не изменяет shell-профили. Внутри Qwen доступны `/model`, инструменты, MCP и обычные команды. По умолчанию применяется `--approval-mode=yolo`, как в командной инструкции; это переключается в настройках. Внутренний Python-лаунчер сохранён для запуска терминала и работы гейтвея.

Для минимальной Ubuntu/Debian дополнительно нужны системные библиотеки интерфейса и LM Studio. В обычной настольной установке большая часть уже есть:

```bash
sudo apt-get install libgl1 libegl1 libx11-6 libxi6 libxcursor1 libxrandr2 libxinerama1 libxkbcommon0 libxkbcommon-x11-0 libwayland-client0 libwayland-cursor0 libwayland-egl1 libdbus-1-3 libatomic1 libgomp1 xterm
```

`libatomic1` требуется официальному установщику LM Studio. Если системного пакета не хватает, приложение показывает сообщение установщика с командой установки.

## Что устанавливается

| Компонент | Источник / поведение |
|---|---|
| Интерфейс | Rust + egui, без браузерного движка |
| Qwen Code + Node.js | Официальный standalone-установщик Qwen; существующая standalone-установка используется повторно |
| LM Studio | Существующая LM Studio Desktop или официальный фоновый runtime **llmster**, без отдельного окна LM Studio |
| Локальная модель | `huihui-ai/Huihui-Qwen3.8-27B-abliterated-GGUF`, `Huihui-Qwen3.8-27B-abliterated-Q4_K.gguf`, 16.8 GB |
| Python | Автоматически скачиваемый собственный runtime с проверкой SHA-256; системный Python и pip не нужны |
| Гейтвей и загрузчик | Встроены в исполняемый файл; исходники находятся в `backend/` |

Версия модели и её SHA-256 закреплены в [local-model.json](backend/config/local-model.json). Python закреплён в [runtime-manifest.json](assets/runtime-manifest.json). Скрипты загрузки Qwen и LM Studio берутся с официальных HTTPS-адресов при установке. Они устанавливают актуальные версии поставщиков; уже установленный Qwen можно обновлять штатным `/update`.

Модель требует до **34 GB свободного места** на время скачивания и сборки частей, после чего остаётся 16.8 GB. Для быстрого редактора желательна NVIDIA с 24 GB VRAM; загрузчик учитывает свободную видеопамять и допускает частичную выгрузку на CPU. Без обнаруженной NVIDIA используется CPU при достаточной RAM; редактирование на CPU существенно медленнее. Полный GPU offload не гарантируется, если память занята другими приложениями. Модель загружается в память только при необходимости исправить отклонённый запрос.

## Маршрут запросов

Установка Supa Dev не запускает API LM Studio: он нужен только при правке отклонённого запроса. После каждой правки, успешной или неудачной, гейтвей запрашивает выгрузку редактора. На случай сбоя очистки загрузчик задаёт модели TTL 60 секунд простоя. Следующая правка заново проверяет готовность модели.

Кнопка **Остановить и выгрузить редактор** сначала запрещает повторную загрузку, затем выгружает только модель редактора. **Включить редактор** снимает запрет без немедленной загрузки. Облачный Qwen, `/model` и инструменты продолжают работать. При зависании выгрузки приложение показывает ошибку, а не сообщает об успехе. Фоновый llmster и отдельные терминалы могут оставаться запущенными; другие модели пользователя не выгружаются и процессы по общему имени не завершаются.

Для проблемы с завершением процесса в Windows есть [диагностика процессов](scripts/diagnose-processes.ps1). Скрипт сохраняет `supa-processes.json` на рабочем столе: PID, родитель, память и результат проверки прав на завершение. Он не запускает модели, не завершает процессы и не собирает ключи/историю. Доступ к завершению не доказывает, что завершение действительно сработает: для такого случая нужен текст ошибки Windows.

```text
Qwen Code → localhost:1236 → облачный Qwen
                                  │ HTTP 400
                                  ↓
                        локальный редактор :1234
                                  │ изменённый текст
                                  ↓
                            облачный Qwen
```

Локальная модель **только редактирует текст**. Она не получает исполняемых инструментов, не выполняет задачу, а её ответ не подставляется вместо облачного ответа. Гейтвей сохраняет роли, системные инструкции, вызовы инструментов, параметры, пути и числовые значения. Он может нейтрализовать постороннюю грубую или откровенную прозу в истории, сохраняя техническую задачу. Это не гарантирует принятия любого запроса: после двух неудачных циклов возвращается ошибка облака.

Модель, выбранная через `/model`, сохраняется между запусками. Выбор в приложении применяется вновь, когда вы меняете его в настройках. Пользовательские инструменты и MCP не отключаются. Порт гейтвея по умолчанию 1236, чтобы не конфликтовать с прежним локальным артефактом на 1235.

## Ключи и обновления

Командный ключ **не включён** в код или сборку. Каждый разработчик вводит свой ключ в приложении. На Windows ключи защищены DPAPI текущего пользователя, на Linux хранятся в каталоге с правами 0700 и файле с правами 0600. В обычный журнал ключи и тела запросов не записываются.

Репозиторий и релизы публичные. Для скачивания и обновления GitHub-токен или авторизация не нужны.

Приложение автоматически проверяет последний стабильный релиз после завершения мастера и раз в 6 часов. Используются [публичные ссылки Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/linking-to-releases), без REST API и его лимита запросов для общего IP. В фоне скачивается сборка для своей ОС, проверяется SHA-256 и появляется модальное окно **«Найдено обновление. Обновиться?»** с кнопками **«Обновиться»** и **«Позже»**. Диалог не прерывает мастер или текущую установку. После выбора «Позже» скачанный файл сохраняется; ту же версию не предлагают повторно в текущем сеансе. Установить её можно из раздела «Обновления». Сбой проверки не блокирует работу и повторяется через 30 минут. Старая версия программы сохраняется рядом как `.previous`. Запущенные терминалы работают независимо от интерфейса. Гейтвей обновляется при следующем запуске, когда у него нет активного запроса. Не закрывайте приложение во время установки; сначала нажмите **Отменить**.

Настройки, собственный Python, скрипты и загрузки находятся в локальном каталоге данных SupaDev (путь виден в настройках), рабочий кэш — в выбранной папке `qwen`. Переменная `SUPA_DEV_HOME` позволяет задать отдельный каталог приложения. Профиль Qwen хранится отдельно в `qwen-profile`; при первом запуске копируются существующие настройки без блока с ключами. Мастер запоминает завершение, а ключ и модель впоследствии меняются в настройках. Алиасы, созданные старыми версиями, остаются независимыми от интерфейса.

## Разработка и релизы

Требования для сборки: Rust 1.93, Node.js 22+, Python 3.10+ для тестов; для Windows — MSVC Build Tools. На Linux нужны заголовки X11/Wayland/OpenGL (список в workflow).

```powershell
# Windows
./scripts/build.ps1
python backend/scripts/test-gateway-repair.py --synthetic-only
python backend/scripts/test-runtime.py
```

```bash
# Linux
bash scripts/build.sh
python3 backend/scripts/test-gateway-repair.py --synthetic-only
python3 backend/scripts/test-runtime.py
```

`cargo fmt --check` и `cargo test --locked` проверяют Rust. `supa-dev --diagnose` скачивает собственный Python при необходимости и выводит состояние компонентов в JSON, не создавая алиас и не выполняя облачные задачи. `--bootstrap` только разворачивает runtime. Для изолированной проверки задайте `SUPA_DEV_HOME`.

`--check-updates` проверяет публичный релиз без интерфейса. `--download-update` скачивает и проверяет последний релиз даже при совпадении версии; эта диагностическая команда не устанавливает обновление и не перезапускает программу.

GitHub Actions проверяет оба целевых окружения. Тег `vX.Y.Z`, соответствующий версии в `Cargo.toml`, запускает сборку Windows/Linux и публикует обе программы с `SHA256SUMS` в Releases. В репозиторий включены нужные скрипты из исходного рабочего окружения; история чатов, проекты, кэш, диагностические запросы и ключи исключены.

Официальные источники: [Qwen Code](https://github.com/QwenLM/qwen-code), [LM Studio headless](https://lmstudio.ai/docs/developer/core/headless), [Python](https://www.python.org/downloads/), [Python Build Standalone](https://github.com/astral-sh/python-build-standalone), [репозиторий модели](https://huggingface.co/huihui-ai/Huihui-Qwen3.8-27B-abliterated-GGUF).

## Проверка в Docker без локальной модели

В `scripts/docker-smoke/` находится изолированный сценарий для Ubuntu 22.04. Он скачивает опубликованный Linux-бинарник, проверяет SHA-256, устанавливает собственный Python, реальный Qwen Code и LM Studio runtime, запускает гейтвей и интерфейс на Xvfb, открывает терминал с путём проекта, содержащим пробелы. Файлы GGUF и инференс локальной модели не используются.

```bash
docker build -t supa-dev-smoke scripts/docker-smoke
docker run -d --name supa-dev-smoke --memory 4g --cpus 4 --mount "type=bind,source=$PWD,target=/repo,readonly" supa-dev-smoke
docker exec supa-dev-smoke bash /repo/scripts/docker-smoke/run.sh
docker exec supa-dev-smoke /home/tester/supa-data/runtime/python-3.13.18/python/bin/python3 /repo/scripts/docker-smoke/update-smoke.py
```

`update-smoke.py` проверяет общий с фоновым обновлением загрузчик через `--download-update`, замену старой программы, резервную копию, перезапуск и сохранность настроек/ключа. `SUPA_TEST_BINARY` позволяет проверить ещё не опубликованный бинарник, а `SUPA_TEST_VERSION` — выбрать релиз для основного сценария. `cloud-smoke.py` — отдельная необязательная проверка реального облачного Qwen: ключ поступает через stdin и восстанавливается после проверки. Облачная модель должна прочитать файл со случайным содержимым через инструмент. Отчёты находятся в `/home/tester/reports`; их можно забрать через `docker cp`. Это проверка Linux-сборки; она не подменяет проверку нативного Windows-терминала и Windows-механизма замены exe.
